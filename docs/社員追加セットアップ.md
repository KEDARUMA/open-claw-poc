# AI社員セットアップ手順

## 目的

ターミナルから指示文書に沿って作業するツール（Codex CLI）を使い、既存の指示ファイルを再利用してOpenClawへAI社員6名を登録する。依頼の割り振りを担うマネージャーと、設計・デザイン・開発・レビュー・テストを担う社員で構成する。対象はWindows 11の本プロジェクトである。

PowerShellでプロジェクトルート（このリポジトリを配置したディレクトリ）に移動してから実行します。

```powershell
codex exec --approve-for-me --cd . "docs/社員追加セットアップ.md を読み、この手順を実行してください。認証など人の操作が必要になったら、その場で停止して案内してください。"
```

Codexは各工程の完了条件を確認しながら進める。認証や既存設定の競合など、安全に自動処理できない状態が見つかった場合は、変更を広げず停止して報告する。

## 作業範囲

- OpenClaw、Node.js、Codex認証の準備には、既存の [`openclaw-setup.md`](openclaw-setup.md) を使う。
- OpenClawのローカル設定 `.openclaw/openclaw.json` に6名を登録する。社員が指示を読み作業する専用ディレクトリ（workspace）も各人に設定する。
- Git管理済みの共通・社員別 `AGENTS.md` と `SOUL.md` はそのまま使う。新規作成、コピー、上書きはしない。
- チャット接続と社員の実行を担う常駐プロセス（Gateway）や、状態確認・操作を行うブラウザー画面（Control UI）は起動しない。設定前のGateway稼働状態を保つ。
- チャネル連携や追加の社員は設定しない。

## 1. 作業対象と既存ファイルを確認

1. `git rev-parse --show-toplevel` でGitルートを特定し、そのルートに `AGENTS.md` と `docs/社員追加セットアップ.md` があることを確認する。どちらかがない場合は停止する。
2. `AGENTS.md`、`.openclaw/workspaces/AGENTS.md` と、存在する場合は `.openclaw/workspaces/MACHINE-SPECIFIC.md` を読む。後者がない場合は新規作成せず、未配置として報告する。
3. `git status --short` を確認し、作業前からある変更を記録する。今回の作業と無関係な変更は編集しない。
4. 下表のファイルが存在し、Git管理されていることを確認する。欠落や、後述する `SOUL.md` の正本との不一致があれば、作り直さず停止して報告する。

| 種別         | 確認するファイル                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------ |
| 共通ルール   | `.openclaw/workspaces/AGENTS.md`                                                                 |
| 社員別ルール | `.openclaw/workspaces/{main,architect,designer,engineer,reviewer,qa}/AGENTS.md`                  |
| 社員別役割   | `.openclaw/workspaces/{main,architect,designer,engineer,reviewer,qa}/SOUL.md`                    |
| 役割の正本   | `ai-employees/employee-profiles/roles/{manager,architect,designer,engineer,reviewer,qa}/SOUL.md` |

各社員の `SOUL.md` が対応する役割の正本と一致することも確かめる。社員別 `AGENTS.md` は親ディレクトリの共通ルールを継承し、各ファイルに個別の指示を持つ。共通ファイルとの内容一致は要求しない。`ai-employees/employee-profiles/common/AGENTS.md` は実際に読み込まれる共通ルールではないため、配布元に使わない。

## 2. OpenClawとCodex認証を準備

既存の [`openclaw-setup.md`](openclaw-setup.md) に従い、プロジェクト内のNode.jsとOpenClaw CLIを確認する。必要な場合だけ同書のインストール手順を実行する。版が想定と異なる既存ランタイムは上書きせず、そこで停止する。

Codexサブスクリプション認証が未設定なら、`openclaw-setup.md` のCodex認証手順を案内して停止する。ユーザーがデバイス認証を終えた後、上記の `codex exec` コマンドを再実行してもらう。個人用のCodex設定や認証ファイルを探索・コピーしない。

既存導入手順のうち、Gateway起動、ブラウザー起動、Control UI表示の工程は実行しない。設定前後にGatewayと18789番ポートの状態を記録する。

- Gatewayの稼働状態は `gateway status --require-rpc` で確認する。
- PowerShellでは `Get-NetTCPConnection -LocalPort 18789 -State Listen -ErrorAction SilentlyContinue` を使い、ポートの待受を確認する。

Gatewayは起動、停止、再起動しない。

## 3. ローカル設定を安全に更新

OpenClawのCLIは `scripts/openclaw-control.ps1 cli` 経由で呼び出す。設定ファイルを読む前に内容を画面やログへ出さない。

`.openclaw/openclaw.json` がなければ、既存導入手順の設定手順に沿って初期化する。Gateway起動の節には進まない。設定を編集する直前に、既存ファイルを `.openclaw-runtime` 配下へバックアップする。JSONとして読めない場合は停止し、初期化・削除しない。

次の設定だけを追加・補完し、ほかの設定や追加済みエージェントを保持する。すでに登録済みの同一IDに異なる役割・ワークスペースが設定されていたら、上書きせず停止する。既定モデルは値がある場合は保持し、未設定の場合だけ既存導入手順の `openai/gpt-6-astra` を使う。Gatewayモードも未設定の場合だけ `local` にする。

社員が委任先として指定できる相手を制限する設定（`subagents.allowAgents`）を、次の表に示す。

| 登録ID（agent ID） | 表示名             | workspace                        | `subagents.allowAgents`                               |
| ------------------ | ------------------ | -------------------------------- | ----------------------------------------------------- |
| `main`             | マネージャー       | `.openclaw/workspaces/main`      | `architect`, `designer`, `engineer`, `reviewer`, `qa` |
| `architect`        | ソフトウェア設計者 | `.openclaw/workspaces/architect` | 空配列                                                |
| `designer`         | UI/UXデザイナー    | `.openclaw/workspaces/designer`  | 空配列                                                |
| `engineer`         | Webアプリ開発者    | `.openclaw/workspaces/engineer`  | 空配列                                                |
| `reviewer`         | レビュワー         | `.openclaw/workspaces/reviewer`  | 空配列                                                |
| `qa`               | QA                 | `.openclaw/workspaces/qa`        | 空配列                                                |

workspaceはプロジェクトルートからの絶対パスにする。設定のキー構成は既存ファイルとOpenClaw CLIのスキーマに合わせてマージする。完成形に次の値を含める。

既存設定はOpenClaw CLIの `config set` で必要なキーだけ更新する。保護されたマップへ項目を加えるときは `--merge` を使うか、その項目の下位キーを個別に設定する。`agents.entries`、`plugins.entries`、`models.providers` 全体を置き換えない。配列や真偽値は `--strict-json` で指定する。

```text
agents.ownership = "explicit"
agents.defaults.skipBootstrap = true
agents.defaults.systemAgent.agentId = "main"
plugins.entries.codex.enabled = true
plugins.entries.codex.config.appServer.homeScope = "agent"
models.providers.openai.agentRuntime.id = "codex"
```

`skipBootstrap` は既存ワークスペースへのOpenClaw標準ファイルの自動生成を止める。登録後も、追跡済みの `AGENTS.md` と `SOUL.md` は読み込まれる。

設定を書き換えたらJSONとして再読込する。再読込に失敗した場合はバックアップから戻し、Gatewayには触れずに停止する。

## 4. 登録結果を確認

次のコマンドを実行する。検証、一覧確認、期待値との照合のいずれかに失敗した場合は、設定をバックアップから戻して停止する。初期設定から作ったファイルにバックアップがない場合は削除せず、状態を報告する。Gatewayの再起動で解決しようとしない。

```powershell
.\scripts\openclaw-control.ps1 cli config validate
.\scripts\openclaw-control.ps1 cli agents list --json
```

- 指定した6つのagent IDと各workspaceが登録されている。
- `main` が既定のagentであり、他の5名を委任先に持つ。
- ほかの5名は `subagents.allowAgents` が空である。
- 6名の各ワークスペースに既存の `AGENTS.md` と `SOUL.md` が残っている。
- Codex plugin、agentごとのCodexホーム分離、Codexランタイムが設定されている。
- Gatewayと18789番ポートの状態が作業前から変わっていない。

## 5. 完了報告

変更したファイル、6名の登録結果、設定検証結果、Gatewayの作業前後の状態を報告する。認証情報やトークンは含めない。

Gatewayを起動していないため、次の確認は未実施と明記する。

- Control UIの表示
- AI社員の応答
- チャネル連携
- テスト
